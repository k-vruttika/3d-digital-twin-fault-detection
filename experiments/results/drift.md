# Drift detection on the operating-condition inputs

Generated by `uv run poe drift-report` (2026-11-20T14:34:27+00:00, dataset `944580196604b618`). Every number comes from running the live detector code on the simulator's clean runs; see ADR 0031.

## What is measured

- **Inputs:** speed, load (operating-condition inputs; health signals are not monitored for drift because a developing fault changes them by design).
- **PSI** of the last 120 operating rows against the training distribution of the machine's kind (10 quantile bins of the training rows inside the 0.1% to 99.9% support, plus an overflow bin on each side; additively smoothed counts).
- **Alert level per kind and channel:** the 99.9% quantile of the PSI of clean *validation* windows, times the live margin. A machine sits in one load band for long stretches, so the textbook 0.25 would flag clean runs.
- **Decision:** PSI at or above the alert level for 30 s raises drift; it clears below 0.85 x the alert level for 60 s. ADWIN (delta 0.002) only dates the change.

## Detection of synthetic input shifts (test runs, at the chosen margin)

## ADWIN dating of the change

Through the full monitor on 12 test runs with a +45 pp load shift: the reported start of the drift (`since`) minus the true shift time, median 20 s, p90 23 s over 8 dated runs (negative = reported before the shift).

## Limits

- Drift is measured on speed and load only. It says the conditions differ from the training data, not that the predictions are wrong.
- Windows of one run are strongly correlated, so the false-drift rate is a rate over a small number of independent runs; read it as an order of magnitude.
- Simulator data only. The shifts are synthetic edits of recorded rows.
